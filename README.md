# Pink Wardrobe

Бесплатный личный гардероб на русском языке: фотографии одежды, образы по погоде, избранное и предпочтения. React + TypeScript + Vite, Motion, Lucide, IndexedDB/Dexie, PWA. Без регистрации, сервера, ключей API и платного AI. Подбор — объяснимый алгоритм правил, а не внешняя нейросеть.

## Запуск

Нужен Node.js 22.12+ (рекомендуется актуальный LTS).

```powershell
cd C:\Users\Пользователь\Documents\Codex\pink-wardrobe
npm.cmd ci
npm.cmd run dev
```

Откройте http://localhost:5173. Если node/npm недоступны через PATH, можно использовать установленный Node напрямую; глобальные инструменты не нужны.

Production и проверка PWA:

```powershell
npm.cmd run build
npm.cmd run preview
```

Откройте http://localhost:4173. Для телефона в той же Wi-Fi-сети откройте сетевой адрес из терминала (при текущем запуске: http://192.168.0.11:4173). Компьютер должен оставаться включённым; доступ зависит от брандмауэра и отсутствия изоляции Wi-Fi-клиентов. Адрес компьютера может меняться. Локальный HTTP позволяет пользоваться интерфейсом, но установка PWA и service worker на телефоне требуют HTTPS.

## Первый запуск и использование

1. Введите имя по желанию. Начните с личного гардероба либо выберите отдельно помеченное демо.
2. В гардеробе добавьте фото из галереи или камеры, категорию, цвета, стиль и температурный диапазон. Фото обрабатывается на устройстве до 1200px по длинной стороне, JPEG quality 0.84, без изменения пропорций.
3. В «Подборе» задайте температуру, осадки, ветер, повод и стиль. Погода вводится вручную; геолокация не запрашивается.
4. Получите до трёх разных вариантов. Если данных или подходящих вещей недостаточно, приложение покажет недостающие категории.
5. Сохраните образ в избранное, поставьте оценку. Оценки влияют на будущий рейтинг вещей и сочетаний.
6. Настройте любимые цвета, стили, исключения, комфортный диапазон и многослойность.

В демо нет зимней/дождевой верхней одежды: отказ для холода и осадков ожидаем. Демопараметры условны. Ваши вещи и демовещи никогда не участвуют в одном образе. Добавление собственной вещи из деморежима переключает в личный гардероб. Удаление вещи также удаляет избранные образы и оценки, ссылающиеся на неё.

## Данные и резервные копии

Все фотографии, вещи, образы и настройки находятся в IndexedDB текущего браузера, в рамках текущего origin (протокол + адрес + порт). Гардеробы на localhost, 127.0.0.1, сетевом IP и опубликованном домене — отдельные. Для переноса используйте резервную копию.

«Настройки → Экспортировать копию» скачивает JSON вместе с фотографиями обеих коллекций. «Восстановить из файла» сначала проверяет формат, поля, фото-data-URL и ссылки образов на вещи, затем после подтверждения атомарно заменяет данные. Перед восстановлением можно скачать текущую копию. Лимит импорта 100 МБ / 2000 вещей; фотографии в копии должны быть JPEG, PNG или WebP base64.

Очистка данных сайта, приватный режим и освобождение браузером места могут удалить локальную базу. Регулярно сохраняйте копии. Фото HEIC поддерживается, только если браузер умеет декодировать файл; при ошибке выберите JPEG/PNG/WebP. Удаление фона и распознавание одежды не выполняются: фотографируйте вещи целиком на спокойном фоне.

## Алгоритм

`src/engine.ts` фильтрует вещи по температурным диапазонам и пригодности внешнего слоя/обуви к осадкам. При ветре от 8 м/с расчётная температура снижается на 3 °C; ниже личного комфортного диапазона — ещё на 2 °C, выше — повышается на 2 °C (в пределах −25…+40). Обязательная композиция — платье либо верх + низ, плюс обувь; ниже 15 °C, при осадках или сильном ветре в прохладу добавляется внешний слой.

Рейтинг учитывает нейтральные, аналогичные и комплементарные цвета (также второй цвет), стиль, повод, любимые цвета, оценки и историю показов. Пары цветов из исключений и сочетания sporty/romantic отсеиваются. Варианты имеют разные веса комфорта/слоёв и разнообразия. Если комбинаций меньше трёх, показывается действительное количество. Сезон хранится как метаданные и фильтр; пригодность по погоде определяется явным диапазоном °C, чтобы пользовательница управляла ею точнее.

## Установка PWA

На HTTPS или localhost после первого открытия кэшируются приложение, локальные шрифты и демофото. Личные фото доступны из IndexedDB. Автономный режим проверен перезагрузкой с отключённой сетью в автоматизированном Edge.

- iPhone / Safari: «Поделиться → На экран “Домой”».
- Android / Chrome: меню → «Установить приложение» / «Добавить на главный экран». При доступном beforeinstallprompt кнопка в настройках вызывает системный диалог.
- Безопасные зоны iOS учтены через viewport-fit и env(safe-area-inset-*).

Физические iPhone/Android и установка на реальные домашние экраны в этой среде не проверялись. Эмуляция размеров не заменяет тест на устройстве.

## Проверки

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

Playwright по умолчанию использует установленный Microsoft Edge по стандартному Windows-пути. Для другого установленного Chromium задайте переменную окружения `PW_BROWSER` с полным путём к исполняемому файлу. Пример для Windows:

```powershell
$env:PW_BROWSER = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm.cmd run test:e2e
```

E2E тестирует реальную загрузку/сжатие фотографии, сохранение после reload, редактирование, удаление и каскадную очистку избранного, подбор, оценки, настройки, JSON-экспорт/восстановление, отдельное демо, пустое состояние и нижнюю навигацию. Снимки и axe-проверки выполняются на 375/390/430/768/1440px, плюс landscape/reduced-motion. Отчёт — `playwright-report/index.html`, снимки — `qa/screenshots/`. Vitest проверяет температурную матрицу, ссылки только на существующие вещи, совместимость, обратную связь и транзакции копий. Визуальные результаты и фактические ограничения записаны в `qa/REPORT.md`.

## Архитектура

- `src/types.ts` — модель и справочники.
- `src/db.ts` — Dexie, удаление зависимых данных, проверка/импорт/экспорт.
- `src/engine.ts` — чистый алгоритм без сети.
- `src/images.ts` — локальное сжатие с сохранением пропорций.
- `src/demo.ts` — отдельные демонстрационные вещи.
- `src/App.tsx` — экраны, маршруты по hash и сценарии.
- `src/ItemForm.tsx`, `src/components.tsx` — редактор и общие элементы.
- `src/styles.css`, `DESIGN.md` — токены и адаптивная дизайн-система.
- `tests/unit`, `tests/e2e` — проверки.
- `public/demo/credits.json` — происхождение каждого демофото.

Использован обычный CSS вместо Tailwind: единые токены и адаптивные правила без дополнительной зависимости. Motion обеспечивает переходы, stagger, реакцию на нажатия, смену образа, модальные окна и reduced-motion. Библиотеки и шрифты поставляются локально. Единственная внешняя ссылка в интерфейсе — источник демофотографий.

## Публикация на бесплатном хостинге

Основной адрес публикации: https://boef210220061-coder.github.io/garderob/ . Репозиторий: https://github.com/boef210220061-coder/garderob . Workflow `.github/workflows/deploy.yml` собирает и публикует приложение при push в main. В Settings → Pages выберите Source: GitHub Actions. Готовая папка `dist` — статический сайт; сервер приложению не требуется. Можно вручную загрузить её на статический хостинг с HTTPS (например, Cloudflare Pages / Netlify). Для сборки из репозитория: команда `npm ci && npm run build`, выходная папка `dist`, Node 22+. Для GitHub Pages workflow задаёт `PAGES_BASE_PATH=/garderob/`: base, манифест, scope service worker, иконки и демофото поддерживают подпапку. При локальной сборке без этой переменной используется корень `/`.

Перед публичным/коммерческим распространением замените демофото своими лицензированными изображениями либо отдельно подтвердите права на них: DummyJSON предоставляет тестовые каталожные ресурсы, индивидуальный автор/лицензия каждого изображения не заявляются. В приложении они явно отмечены как демо и имеют ссылку на источник. Шрифт Golos Text Variable поставляется локально с OFL-лицензией в npm-пакете.

- **design-taste-frontend**: app-screens workflow, выбор editorial-greeting (seed 2002889412), реальные браузерные измерения, снимки и итерации visual QA.
- Отдельные Test Skill, frontend-design, animation, responsive-design, accessibility и Playwright skills не обнаружены в доступном каталоге и локальном проекте. Аналоги: инструкции UI UX Pro Max / design-taste, реальные Vitest, Playwright и axe. Неизвестные глобальные skills не устанавливались.

Технические первоисточники: [Vite](https://vite.dev/guide/), [Dexie transactions](<https://dexie.org/docs/Dexie/Dexie.transaction()>), [PWA](https://vite-pwa-org.netlify.app/guide/), [Motion accessibility](https://motion.dev/docs/react-accessibility).

Для повторного запуска готовой сборки в Windows можно дважды открыть start.cmd из папки проекта. Чтобы увидеть изменения исходников в production-preview, сначала выполните npm.cmd run build. На телефоне после успешного подбора сразу открывается композиция; «Изменить погоду» возвращает к параметрам.

При открытии с телефона данные сохраняются только в браузере телефона. Личный гардероб с компьютера переносится через резервную копию; он не публикуется в GitHub.
